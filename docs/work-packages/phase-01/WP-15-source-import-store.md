## Objective and traceability

Implement the ten-symbol `source-import-store.v1` API in
[ADR-0018](../../adr/ADR-0018-atomic-sqlite-source-import.md). On a caller-owned
SQLite connection, initialize a new synthetic/local store for one explicitly
supplied active source, reconstruct one consistent committed generation, and
atomically persist a complete current snapshot as immutable Raw revisions,
nondeleting membership and durable `change_events` under one `import_id`.

This is the first persistence slice after WP-09/10 validation, WP-11/13 source
scope and WP-14 Raw encoding. It must rerun those accepted contracts against the
state loaded inside `BEGIN IMMEDIATE`, reject a stale generation and make exact
retry idempotent. It addresses Roadmap 4.3, 5.2 step 5, 15.3 and O-80 without
wiring the watcher or claiming a complete operational import. G1 remains open.

Read ADR-0018 in full. Its schema, API fields, event bytes/hash chain, transaction
ownership, error semantics, one-source bootstrap boundary and limits are normative.
All databases, rows, UUIDs, timestamps and workbooks used here are generated
synthetic fixtures. Never inspect or modify `data/accounting.sqlite3`, a real
workbook/database copy, OneDrive data, credentials or production state.

## Required implementation behavior

- Use only the accepted WP-04/09/10/11/13/14 public contracts for validation,
  scope, planning and Raw encoding. Do not duplicate their tables or silently
  loosen their rules. Never trust a caller plan, revision, count or sequence.
- Start the owned write unit with `BEGIN IMMEDIATE`. Check exact-import replay
  before stale generation, then validate the expected generation and event IDs.
- Append one immutable revision/event for each INSERT/EDIT/VOID, none for
  UNCHANGED. Record membership for every current row and retain tombstones.
- Store exact WP-14 bytes only for ACTIVE revisions. VOID Raw/source hash are null;
  old Raw stays immutable. Use event payload/hash/previous-version rules from the
  ADR and consecutive sequence numbers with no committed gaps.
- Insert one import and exactly four sheet records, update source last-observation
  metadata, and advance generation once in the same transaction. A zero-event
  successful import still has a report but does not advance event sequence.
- Return success only after COMMIT. Roll back all pre-commit failures. An ambiguous
  commit outcome is resolved only by exact `import_id` retry, never by guessing.
- Load a registry/catalog from committed state under one transaction. No import
  may compare generation A and write into generation B.
